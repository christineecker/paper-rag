PubMed Search Anatomy

How a question becomes a reproducible PMID set: framework (PICO / PECO / PCC) shapes the concepts, sensitivity shapes the compilation, and none of it ever touches retrieval. Engine: scripts/lib/pubmed_query.py.

From question to PMIDs

1

Pick a framework Claude / you

Intervention question → PICO, exposure → PECO, scoping → PCC. The choice lives entirely in this step: it decides which concepts exist (PCC has no outcome slot), and the code downstream never branches on it. framework is stored in the result as provenance only.

2

Write the concepts Claude / you

paper-rag has no LLM client, so question mode is unimplemented — a human or Claude turns the question into SearchConcept groups. Each framework slot becomes one {name, terms} object; name is a free-text label, not a fixed vocabulary.

[
  {"name": "population",   "terms": ["autism spectrum disorder", "ASD"]},
  {"name": "intervention", "terms": ["oxytocin"]},
  {"name": "outcome",      "terms": ["social cognition"], "required": false}
]
3

Compile under a sensitivity code

compile_concepts() builds one Boolean query: OR within a concept (MeSH heading + Title/Abstract synonyms), AND across concepts. Terms with expand: true are looked up against the local MeSH index; hits add a [MeSH Terms] clause alongside the free-text ones.

4

ESearch, dedupe, record code

The compiled query runs through ESearch; the result stores the PMIDs together with the exact pubmed_query, mode, framework, sensitivity, and warnings — so the search is re-runnable verbatim later. Optional --funnel adds cumulative per-concept hit counts.

"pubmed_query": "(\"Autism Spectrum Disorder\"[MeSH Terms] OR autism[Title/Abstract] OR ASD[Title/Abstract]) AND (\"Oxytocin\"[MeSH Terms] OR oxytocin[Title/Abstract]) AND (\"social cognition\"[Title/Abstract])"

The sensitivity dial

One parameter, three positions (Sensitivity = Literal["broad", "balanced", "precise"]). It only exists in concepts mode; direct mode passes your query through untouched.

broad recall

Keeps only required: true concepts and drops the optional ones — fewer AND clauses, more hits.

Falls back to all concepts if none are marked required. _select_concepts()

balanced default

All concepts ANDed, every term kept. What you get when you don't ask.

No filtering at either level.

precise precision

All concepts, but short ambiguous abbreviations (single token, ≤4 chars — "MRI", "ASD") are dropped from the free-text clauses.

Never empties a group; emits a reduced-recall warning. _looks_like_ambiguous_abbreviation()

Where the concepts stop: acquisition vs. retrieval

Framework is metadata downstream. All three frameworks compile identically — the compiler sees only {name, terms, required, expand}. The one structural difference is upstream: PCC has no outcome concept, so a scoping search simply arrives with one fewer AND group.

Reproducibility. The compiled pubmed_query is saved next to the PMIDs in every search directory, so any search can be re-run exactly, regardless of who wrote the concepts.
