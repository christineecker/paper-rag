# Concept Graph

`/paper-rag:graph <project>` maps the claims of a [project's](/guide/tags-and-homes) papers onto stable **concept nodes**, records typed **edges** between concepts, and emits a regenerable OKF v0.2 bundle. Claims must exist first: run `/paper-rag:extract-claims --all-missing`.

```
/paper-rag:graph <project>
/paper-rag:graph <project> status | emit | neighbors <concept> | path <a> <b>
/paper-rag:graph <project> review <relation-id> <type> --rationale "..."
/paper-rag:graph <project> reconfirm <relation-id>
```

## What is stored

Everything lives in the project directory, outside the folders `project sync` rebuilds (`chroma/`, `bm25/`, `dashboard/`), so a sync never wipes it.

```
<project>/graph/   concepts.jsonl  mappings.jsonl  relations.jsonl  facets.json  log.jsonl
<project>/graph/okf/  index.md  log.md  concepts/<slug>.md  references/<doc_key>.md   (generated)
```

The JSONL files are the source of truth; `graph/okf/` is regenerated by `emit` and never hand-edited. Claims stay in the **main** home. The graph stores pointers `{doc_key, claim_id, claim_hash}` and never copies claim text. The project's Chroma copy is only used to check that the project is current: if any member's claims differ from main, `graph` stops and asks for `/paper-rag:project sync <name>` (or run `graph.py check --sync`).

## Build steps

1. **Facets.** You choose which claim fields become concept nodes (intervention/exposure, outcome, population, study design or method, other) and whether claims lacking them get concepts derived from their text.
2. **Mention pass.** One agent per paper, five at a time, reads its claims and returns `{claim_id, facet, surface_form}`.
3. **Canonicalize.** One pass over the whole vocabulary: find before create, aliases with provenance, and near-matches shown to you before they are treated as one concept. Existing concepts are never renamed or merged silently.
4. **Edges.**
   - `relation propose` (deterministic): claim pairs from different papers that share a concept set, with opposite `increase`/`decrease` and the same population, comparator and effect measure, become `potential_conflict`. Missing context never produces a conflict. Claims carry no timepoint field, so timepoint is not compared.
   - `relation create-manual`: Claude's judgment for `supports`, `extends`, `replicates` (at least two claims), and `is_a` between concepts (no claims). All start `unreviewed`.
   - `relation review <id> contradicts --rationale "..."` is the only way to get `contradicts`.
5. **Emit** the OKF bundle. Every edge traces back claim, source chunk ids, passage.
6. **Discovery menu:** `neighbors`/`path`, `candidates` (embedding-similar claim pairs no edge links), `gaps` (concept pairs with shared neighbors but no edge), or stop.

## Staleness

`claims.py add` replaces a paper's claims and renumbers ids, so an id alone is not stable. Each pointer carries a `claim_hash` (sha256 of text, evidence span, sorted source chunk ids and structured fields). A pointer is **stale** when its id is gone, its hash differs, or its paper left the project. Stale mappings and edges are flagged (`status` lists them; the bundle marks **STALE**), recomputed at every run, and never deleted. A reviewed decision and its rationale persist. Re-map stale claims with `map`; after re-reading an edge's claims, `relation reconfirm <id>` accepts the new hashes.

## Subcommands (`scripts/graph.py`, all take `--project <name>`)

| Subcommand | Description |
|---|---|
| `check [--sync]` | Verify the project copy of the claims matches main. |
| `facets [--save a,b] [--text-fallback]` | Claims per structured field; save the chosen facets. |
| `claims <doc_key>` | A paper's claims with hashes and current mappings. |
| `concept find\|create\|add-alias\|list` | Concept nodes. `find` returns exact/alias matches and similar candidates (string similarity). |
| `map [--file F]` | Store claim → concept links with `claim_hash`; idempotent. |
| `relation propose\|create-manual\|review\|reconfirm\|neighbors` | Typed edges. |
| `path <a> <b>` | Shortest edge chain between two concepts. |
| `candidates [--threshold 0.85] [--limit 20]`, `gaps [--min-shared 1]` | Discovery. |
| `emit`, `status` | Regenerate `graph/okf/`; counts and stale queue. |

The project [dashboard](/guide/dashboard) shows the emitted bundle as an interactive Graph view (`emit` refreshes it).

Not in v1: library-wide graphs, concept merge/split, automatic `contradicts`.
